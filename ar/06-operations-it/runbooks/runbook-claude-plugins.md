# دليل تشغيل — ملحقات Claude Code (متجر `flygaca-family`)

**الغرض.** تثبيت ملحقات العائلة في Claude Code واستخدامها وصيانتها، بحيث تبدأ كل جلسة —
في أي من المستودعات الثلاثة النشطة وعلى أي واجهة — وقواعد العمل محمّلة مسبقًا بدل إعادة
اكتشافها في كل مرة.

**النطاق.** المتجر موجود في `ay2m/Office`، ويضم أربعة ملحقات: اثنان في هذا المستودع، وواحد في
كل مستودع منتج.

---

## 1. ما هو الموجود

| الملحق | مكانه | ما يغطيه |
| --- | --- | --- |
| `office-docs` | `ay2m/Office` — `.claude/plugins/office-docs` | ترويسة YAML، خط إنتاج الطباعة، النسخة العربية، بوابة بيانات الكيان |
| `family-orchestrators` | `ay2m/Office` — `.claude/plugins/family-orchestrators` | سير العمل العابر للمستودعات: المزامنة الشاملة، شحن ميزة، المسح الأمني، مراجعة الامتثال |
| `flygaca-product` | `ay2m/FlyGACA` — `.claude/plugins/flygaca-product` | واجهة React، وخدمة Express، وخطوط إنتاج المدونة التنظيمية، ومخطط Postgres، ومسار RAG |
| `captain-adel-service` | `ay2m/Captain-Adel` — `.claude/plugins/captain-adel-service` | المنهج وبنك الأسئلة، وتشغيل مزوّدي النماذج، وطبقة البيانات، والنشر |

الفهرس هو `.claude-plugin/marketplace.json` في جذر هذا المستودع. ملحقا Office مُدرجان بمسار محلي
نسبي، بينما يُدرج ملحقا المنتجين عبر مصدر `git-subdir` يشير إلى مسار داخل مستودعه، فيبقى كل
مستودع مالكًا لملحقه ولا يُنسخ أي محتوى بين المستودعات.

> [!NOTE]
> الملحقات **لا تحلّ محل** الوكلاء والمهارات المرتبطة بكل مستودع في مجلد `.claude/` الخاص به —
> القائمة الواردة في `.claude/agents/README.md` هنا (`doc-smith` و`ar-mirror` و`ksa-compliance`
> و`family-warden` ووكلاء النفاذ إلى السوق)، و`brain-retrieval` و`eval-warden` و`prompt-steward`
> و`site-chrome` في `ay2m/Captain-Adel`، و`run-flygaca` في `ay2m/FlyGACA`. تلك تُحمَّل تلقائيًا
> داخل نسخة العمل نفسها. أما الملحقات فتحمل المعرفة التي تنقص جلسة **خارج** نسخة العمل، إضافة
> إلى سير العمل العابر للمستودعات الذي لا يخص مستودعًا واحدًا. وحيث يلتقي الاثنان —
> `family-warden` هنا و`family-auditor` للقراءة فقط في الملحق — تكون الأولوية لوكيل المستودع.

## 2. التثبيت — Claude Code (الطرفية)

```shell
/plugin marketplace add ay2m/Office
/plugin install family-orchestrators@flygaca-family
```

كرّر `/plugin install <name>@flygaca-family` لكل ملحق تريده. يسأل التثبيت عن **النطاق**:

| النطاق | الأثر |
| --- | --- |
| **User** | لك، في كل المشاريع |
| **Project** | لكل من يعمل على هذا المستودع (يُكتب في `.claude/settings.json`) |
| **Local** | لك، في هذا المستودع فقط |

إذا أظهر ملخص التثبيت `Run /reload-plugins to activate.` فنفّذ الأمر.

المكافئ غير التفاعلي، للبرمجة النصية أو لجهاز جديد:

```shell
claude plugin marketplace add ay2m/Office
claude plugin install family-orchestrators@flygaca-family --scope project
```

`ay2m/Office` مستودع **خاص**، لذا تتطلب إضافة المتجر هوية git لديها صلاحية القراءة. هذا هو التحكم
المقصود بالوصول — المتجر ليس عامًا، ولا يجوز أن يصبح عامًا: فهو يقيم في مستودع الوثائق.

---

## 3. التثبيت — الجلسات السحابية وتطبيق سطح المكتب

- **Claude Code على الويب / الجلسات السحابية.** الأمر `/plugin` لوحة تفاعلية في الطرفية وغير
  متاح هناك. أدرج الملحق بدلًا من ذلك ضمن `enabledPlugins` في `.claude/settings.json`.
- **تطبيق Claude لسطح المكتب.** استخدم متصفح الملحقات داخله بدل الأمر النصي.
- **Cursor وVS Code وJetBrains.** الملحقات ميزة في **Claude Code** لا في المحرر. تحصل عليها
  بتشغيل Claude Code داخل المحرر — في طرفيته المدمجة أو عبر إضافة المحرر — وتعمل تمامًا كما تعمل
  في طرفية مستقلة. أما صيغة القواعد الخاصة بـ Cursor فنظام منفصل؛ لا تتوقع أن تضبطه هذه
  الملحقات، ولا تنسخ محتواها إلى `.cursor/` حيث ستتباعد النسختان.

## 4. تهيئة عضو جديد (المستودع يتكفّل بالعمل)

تسجّل المستودعات الثلاثة المتجر الآن في إعداداتها، فيحصل الزميل الذي يمنح الثقة للمجلد على
الفهرس دون أن يُطلب منه إضافته:

```json
{
  "extraKnownMarketplaces": {
    "flygaca-family": {
      "source": { "source": "github", "repo": "ay2m/Office" }
    }
  }
}
```

تسجيل المتجر **لا يثبّت شيئًا**. والملحق ذو المصدر الخارجي — وهو حال كل مدخل `git-subdir` هنا —
يبقى بحاجة إلى تثبيت صريح؛ يعرضه Claude Code على أنه غير مثبَّت ويطبع أمر
`claude plugin install` المطلوب. وهذا مقصود: لا تبدأ جلسة أحدهم بتنفيذ محتوى ملحق لمجرد أنه
استنسخ مستودعًا.

اليوم الأول لمهندس جديد، بالترتيب:

1. استنساخ المستودع ومنح الثقة للمجلد.
2. `/plugin install <ملحق هذا المستودع>@flygaca-family`.
3. `/plugin` ← تبويب **Installed** للتأكد مما حُمِّل، وتبويب **Errors** إن غاب أمر أو وكيل.
4. قراءة `CLAUDE.md` الخاص بالمستودع. يبقى هو المرجع — الملحق وسيلة توزيع لقواعده لا بديل عنه.

## 5. صيانة ملحق

محتوى الملحق ملفات Markdown عادية بترويسة YAML، فتعديله تعديل ملف في المستودع الذي يملكه.

- **الوكلاء** في `agents/*.md`: `name` يطابق اسم الملف، و`description` مكتوب بلغة المهمة
  ("use proactively when…")، و`model` مُغفل ليرث الوكيل نموذج الجلسة.
- **الأوامر** في `commands/*.md` وتُستدعى بمساحة اسم الملحق — `/flygaca-product:verify`.
  (يقترح Claude Code الآن `skills/<name>/SKILL.md` للملحقات الجديدة؛ أبقيناها أوامر مسطّحة لأنها
  إجراءات يستدعيها المستخدم وتستخدم `argument-hint` و`allowed-tools`. تُراجَع إن تغيّر ذلك.)
- **ارفع `version`** في `.claude-plugin/plugin.json` عند تغيّر السلوك، وكذلك `version` المقابل في
  مدخل `marketplace.json` في هذا المستودع.
- **تحقّق قبل الدفع**: `claude plugin validate <path-to-plugin>` يشغّل الفحص نفسه الذي يشغّله
  خط المراجعة. وللاختبار محليًا دون تثبيت: `claude --plugin-dir ./.claude/plugins/<name>` ثم
  `/reload-plugins` بعد كل تعديل.
- **لا تضع مطلقًا `agents/` أو `commands/` أو `skills/` أو `hooks/` داخل `.claude-plugin/`.**
  لا يوضع هناك سوى `plugin.json`، وما عداه في جذر الملحق. هذا أشيع خطأ بنيوي.

**أين يتغيّر المحتوى.** ملحقا المنتجين ملك لمستودعيهما: عدّل `flygaca-product` في
`ay2m/FlyGACA` و`captain-adel-service` في `ay2m/Captain-Adel`. ولا يوجد هنا سوى مدخل الفهرس.
وأي ملحق يناقض وكيلُه ملف `CLAUDE.md` في مستودعه فالخلل في الملحق لا في `CLAUDE.md`.

### ملاحظة بشأن بوابة الوثائق

`.claude/` مُدرج ضمن `SKIP_DIRS` في `check.mjs` و`build.mjs` و`build-html.mjs`، لذا لا يحتاج
محتوى الملحقات إلى ترويسة YAML ولا إلى ملف PDF في `_print/`. وهذا الاستثناء مرتبط بالجذر —
فيجب أن تبقى الملحقات تحت `.claude/plugins/`. أما هذا الدليل فوثيقة عادية تخضع للقواعد المعتادة.

## 6. الأمن

تعمل الملحقات بصلاحياتك ويمكن أن تحمل خطّافات (hooks) وخوادم MCP. ملحقاتنا لا تحمل أيًّا منها
اليوم — فهي وكلاء وأوامر، أي تعليمات — لكن القاعدة قائمة: **لا تضف متجرًا ولا تثبّت ملحقًا إلا
من مصدر تثق به.** وراجع أي تعديل على ملحق كما تراجع تعديلًا على التكامل المستمر.

تحذيران خاصان بالعائلة:

- المتجر مستضاف في مستودع الوثائق الذي يضم مواد قانونية ومالية وموارد بشرية ومستثمرين حقيقية.
  ويجب ألا يقتبس محتوى الملحقات منها شيئًا.
- إذا اكتسب ملحق يومًا خطّافًا أو خادم MCP أو ملفًا تنفيذيًا في `bin/`، فتلك مراجعة أمنية لا
  تعديل وثائق — وتُوجَّه حسب [`01-governance/SECURITY.md`](../../01-governance/SECURITY.md).

## 7. معالجة المشكلات

| العَرَض | السبب / الحل |
| --- | --- |
| `/plugin` أمر غير معروف | إصدار قديم من الأداة. حدّث Claude Code وأعد تشغيل الطرفية. |
| المتجر غير موجود | لم يُضف في هذا النطاق: `/plugin marketplace add ay2m/Office`. |
| الملحق يظهر غير مثبَّت بعد الاستنساخ | متوقع للمصادر الخارجية — نفّذ أمر `claude plugin install` الذي يطبعه. |
| اختفاء الأوامر بعد تعديل | `/reload-plugins` (مع `--force` إن حذّر من ذاكرة التخزين المؤقت). |
| ما زالت مفقودة | `rm -rf ~/.claude/plugins/cache` ثم إعادة التشغيل وإعادة التثبيت. |
| فشل إضافة المتجر لمستودع خاص | هوية git لا تقرأ `ay2m/Office`. عالج الصلاحية، ولا تجعل المستودع عامًا. |
