# إجراء تشغيلي قياسي (SOP) — تسجيل القرارات في سجل القرارات

إجراء تشغيلي قياسي لتوثيق قرارات الشركة في `01-governance/decision-log.md`. صُمم ليكون موجزاً وواضحاً ليتسنى لأي عضو جديد تطبيقه من البداية للنهاية دون الحاجة للاستفسار.

يمثل سجل القرارات الذاكرة التوثيقية لـ *أسباب* اتخاذ القرارات في الشركة، ويطلع عليه المستثمرون ومجلس الإدارة والمؤسس مستقبلاً. القرار الذي لا يُسجل يُعد كأنه لم يحدث.

---

## متى يُستخدم هذا الإجراء

سجّل القرار عندما ينطبق **أي** مما يلي:
- **استراتيجي** — يغيّر اتجاه الشركة أو أولوياتها أو هويتها.
- **مكلف التراجع عنه** — قرار باتجاه واحد (One-way door): الاسم، الكيان، التسعير، المزود، أو الموقف القانوني.
- **محل تساؤل محتمل** — سيسأل عنه المستثمر أو الشريك "لماذا اتخذتم هذا القرار؟".
- **عابر للقطاعات** — يمس أكثر من مجال (مثل: القانوني والمنتج، أو المالي والتسويقي).

> عند الشك في استحقاق القرار للتوثيق — **وثّقه فوراً**. التوثيق الإضافي لا يضر؛ بينما إغفال التوثيق يفقد الشركة تفسيراً لا يمكن تقديمه لاحقاً.

---

## خطوات الإجراء

1. **التأكد من أهمية القرار.**
2. **فتح السجل وأخذ الرقم التسلسلي التالي** (مثل `DEC-011`).
3. **تعبئة جدول الترويسة:** التاريخ، القرار، قابلية التراجع، المالك، أصحاب المصلحة المستشارون، وتاريخ المراجعة.
4. **كتابة فقرات التوضيح:** السياق (Context)، الخيارات المدروسة (Options Considered)، والمبررات (Rationale).
5. **تحديد تاريخ المراجعة القادمة.**
6. **التوثيق خلال 7 أيام** من اتخاذ القرار.

---

## قبل الإيداع (Commit) — إعادة بناء ملفات PDF (إلزامي)

سجل القرارات ملف `.md` مدار، ويتطلب نظام CI وجود ملف PDF محدث مطابق تحت `_print/`:

```bash
cd tools/print
npm ci            # للمرة الأولى أو بعد تحديث الاعتماديات
npm run build     # بناء تدريجي — يعيد بناء الملفات المعدلة فقط
node check.mjs    # فحص CI — يجب أن يجتاز بنجاح قبل الإيداع
```
