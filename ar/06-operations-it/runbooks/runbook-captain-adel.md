# دليل تشغيل — نشر الكابتن عادل (دالة RAG السحابية)

تم بناء واجهة دردشة الكابتن عادل (`chat.html`) وهي حيّة. يربط دليل التشغيل هذا
**الدماغ** الكامن خلفها: دالة `chat` السحابية التي تسترجع أقسام GACAR
وتستدعي Gemini للحصول على الإجابة.

إلى أن تُنشر هذه الدالة، تكون صفحة الدردشة صريحة بشأن ذلك — فهي تُظهر
*"لستُ في الخدمة الكاملة بعد، كابتن"* وتوجّه المستخدمين إلى المكتبة القابلة للبحث.
وبمجرد النشر، **لا حاجة لأي تغيير في الواجهة الأمامية**: يستدعي `chat.js` بالفعل
`/api/chat`، الذي توجّهه إعادة كتابة الاستضافة إلى هذه الدالة.

---

## ما تحتاج إليه أولًا

1. **خطة Blaze (الدفع حسب الاستخدام).** لا تعمل Cloud Functions على خطة
   Spark المجانية. ما زالت Blaze تتضمّن طبقة مجانية سخيّة — تكلّف دردشة تعليمية
   منخفضة الحركة القليل — لكن يجب وجود بطاقة فوترة مسجّلة.
   وحدة تحكم Firebase ← مشروعك ← **Upgrade** ← Blaze. اضبط **تنبيه ميزانية**
   (مثلًا 100 ريال سعودي/شهر) وأنت هناك.

2. **مفتاح Gemini API.** اذهب إلى **aistudio.google.com → Get API key**، أنشئ مفتاحًا،
   وانسخه. (أبقِه سرّيًا — فهو لا يُودَع أبدًا في المستودع.)

3. **Firebase CLI**، المثبّتة بالفعل والمسجّل دخولها من نشر المرحلة 1. وإن لم
   تكن: `npm install -g firebase-tools && firebase login`.

## نشر لمرة واحدة

من جذر المستودع (`~/Documents/Claude/flygaca/flygaca`):

```bash
# 1. Install the function's dependencies
cd functions
npm install
cd ..

# 2. Store the Gemini key as a Firebase secret (it prompts you to paste it)
firebase functions:secrets:set GEMINI_API_KEY

# 3. Deploy the function
firebase deploy --only functions
```

يُفعّل أول نشر أيضًا واجهات برمجة تطبيقات Google Cloud المطلوبة (Cloud Functions،
Cloud Build، Artifact Registry، Secret Manager) — وافِق على الطلبات. ويستغرق
بضع دقائق.

عند الانتهاء، تطبع واجهة سطر الأوامر عنوان URL للدالة. أكّد أنها حيّة بطلب
GET عادي من المتصفح — ينبغي أن يُرجع كائن سلامة JSON صغيرًا:

```
https://me-central1-<project>.cloudfunctions.net/chat
→ { "status": "ok", "service": "captain-adel", ... }
```

## الانتقال إلى الإنتاج

الدالة والواجهة الأمامية مربوطتان معًا بالفعل. ما عليك إلا إعادة نشر الاستضافة
لكي تُنشر إعادة كتابة `/api/chat`:

```bash
firebase deploy --only hosting
```

افتح `chat.html`، واطرح سؤالًا عن GACAR (مثلًا *"What are the VFR weather
minima?"*). ينبغي أن يجيب الكابتن عادل باستشهادات الأقسام و**مصادر** قابلة للنقر
تربط بعمق داخل قارئ المكتبة.

> نشر الاستضافة + الدوال معًا يعمل أيضًا:
> `firebase deploy --only hosting,functions`.

## كيف يعمل

```
chat.html  ──POST /api/chat──▶  Hosting rewrite  ──▶  chat() Cloud Function
                                                          │
                                  functions/rag/agent.js  │  Gemini agent loop
                                       │                  │
              search_library / lookup_citation / list_changes
                                       │
                          functions/rag/bm25.js  ◀── _chunks.json.gz
                       (47,361 chunks — 74 Parts, 21 handbooks + 190 reference docs)
```

تُجري الدالة بحثًا معجميًا بخوارزمية BM25 على مجموعة نصوص GACAR، وتسلّم مقاطع
الأقسام المطابقة إلى Gemini (`gemini-2.5-flash`) ضمن موجّه نظام الكابتن عادل،
وتُرجع الإجابة بالإضافة إلى المصادر التي رجعت إليها. لا تضمينات، ولا قاعدة بيانات
متجهات منفصلة — يُبنى الفهرس من ملف مضغوط بحجم ~15 ميجابايت عند الإقلاع البارد
(حُجّمت الدالة عند 2 جيبيبايت لإبقائه مقيمًا)، ثم يُنفَّذ كل استعلام في
أجزاء من الألف من الثانية.

## الضبط والتحكم في التكلفة

| الرافعة | المكان | الافتراضي |
|---|---|---|
| النموذج | متغيّر البيئة `CAPTAIN_ADEL_MODEL`، أو `DEFAULT_MODEL` في `rag/agent.js` | `gemini-2.5-flash` |
| الحد الأقصى للنسخ المتزامنة | `maxInstances` في `functions/index.js` | `10` |
| المنطقة | `region` في `index.js` **و** إعادة الكتابة في `firebase.json` | `me-central1` |
| جولات استدعاء الأدوات لكل دور | `MAX_TOOL_ROUNDS` في `rag/agent.js` | `5` |
| حدّ المعدّل — لكل IP / 10 دقائق | متغيّر البيئة `ADEL_RL_IP` | `40` |
| حدّ المعدّل — اندفاع لكل IP / 30 ثانية | متغيّر البيئة `ADEL_RL_BURST` | `6` |
| حدّ المعدّل — لكل جلسة متصفح / 10 دقائق | متغيّر البيئة `ADEL_RL_SESSION` | `24` |

يعمل الكابتن عادل على `gemini-2.5-flash` — سريع ومنخفض التكلفة وعلى **الطبقة
المجانية** من Gemini API. يمنح `gemini-2.5-pro` استدلالًا أقوى لكنه **ليس** على
الطبقة المجانية (حصة الطبقة المجانية صفر — كل استدعاء يُرجع 429)؛ لاستخدامه، فعّل **الطبقة
المدفوعة** من Gemini API على مشروع Google Cloud الخاص بالمفتاح، ثم عدّل `DEFAULT_MODEL` في
`rag/agent.js` وشغّل `firebase deploy --only functions`.

إذا غيّرت المنطقة، فغيّرها في **كليهما** `index.js` وإعادة كتابة `firebase.json`،
وإلا ستُرجع إعادة الكتابة الرمز 404.

## التحديث لاحقًا

- **هل غيّرت مجموعة النصوص؟** أعد بناء `functions/rag/_chunks.json.gz`، ثم
  `firebase deploy --only functions`.
- **هل غيّرت شخصية الكابتن عادل؟** عدّل `assistant/captain_adel_system_prompt.md`
  (مصدر الحقيقة) **و** اعكس التغيير في
  `functions/rag/system-prompt.js`، ثم أعد نشر الدوال.
- **هل دوّرت مفتاح واجهة برمجة التطبيقات؟** أعد تشغيل `firebase functions:secrets:set GEMINI_API_KEY`
  وأعد النشر.

## المرحلة 10 — التحصين للإنتاج

تجعل المرحلة 10 الكابتن عادل آمنًا لتعريضه لحركة مرور حقيقية وغير موثوقة. بعضها
يُشحن داخل الكود ولا يتطلب منك شيئًا؛ والباقي يحتاج إلى وحدة التحكم.

### موجود بالفعل في الكود — يُشحن مع `firebase deploy --only functions` التالي

- **تحديد معدّل الطلبات** (`functions/rag/ratelimit.js`). يعمل مُحدِّد بنافذة
  منزلقة في كل دور: لكل IP، ونافذة اندفاع قصيرة لكل IP، ولكل جلسة متصفح.
  يحصل الطلب المحظور على HTTP 429 ويُظهر `chat.js` رسالة ودّية
  *"تمهّل لحظة"*. الحدود قابلة للضبط بمتغيّرات البيئة `ADEL_RL_*`
  في الجدول أعلاه. لاحظ الحدّ الصريح: الحالة لكل نسخة Cloud Run
  واحدة، لذا يحمي من إساءة الاستخدام العابرة والحلقات المنفلتة لكن ليس من هجوم
  موزّع — App Check أدناه هي الطبقة التالية.
- **حُرّاس المدخلات** (`functions/rag/guards.js`). إزالة أحرف التحكم،
  وحدود لطول الرسالة والسجل، وكاشف لطيف لحقن الموجّهات — يُحصَّن
  الدور المُعلَّم (تُلحَق ملاحظة أمنية بتعليمة النظام)
  بدلًا من حظره، فلا تُرفض الأسئلة الحقيقية أبدًا بالخطأ. تظهر إشارات
  الحقن في سجلات الدالة.
- **أداة التقييم** (`evals/`). شغّلها بعد أي تغيير على `functions/rag/` أو
  موجّه النظام:
  ```bash
  GEMINI_API_KEY=your_key  node evals/run.js
  ```
  وتخرج بقيمة غير صفرية إذا فشلت أي حالة. راجع `evals/README.md`.

### يحتاج إلى وحدة التحكم — إعدادك لمرة واحدة

**App Check** — يمنع استدعاء الدالة من أي شيء غير
موقعك الحقيقي:

1. وحدة تحكم Firebase ← **App Check**. سجّل تطبيق الويب الخاص بك بمزوّد
   **reCAPTCHA Enterprise** (أو reCAPTCHA v3)؛ وانسخ مفتاح الموقع.
2. في `chat.html` / سكربت تهيئة صغير، هيّئ App Check SDK بذلك
   مفتاح الموقع كي يُرفِق المتصفح رمز App Check بكل طلب.
3. في `functions/index.js`، تحقّق من ترويسة `X-Firebase-AppCheck` بـ
   `appCheck().verifyToken()` التابعة لـ `firebase-admin` وارفض الطلبات التي تفتقر إلى
   رمز صالح. اطرح هذا في **وضع المراقبة** أولًا (سجّل الإخفاقات، ولا
   تحظر) لبضعة أيام، ثم انتقل إلى الفرض.
4. أبقِ `invoker: 'public'` — App Check هي بوابة طبقة التطبيق؛ ويبقى إعداد
   مُستدعي Cloud Run عامًا كي يتمكّن المتصفح من الوصول إلى الدالة
   من الأساس.

**تنبيهات الميزانية** — كي لا تنفلت التكلفة أبدًا دون ملاحظة:

1. وحدة تحكم Firebase ← **Usage and billing** ← اضبط **تنبيه ميزانية** شهريًا
   (مثلًا 100 ريال سعودي) بعتبات بريد إلكتروني عند 50 / 90 / 100 %.
2. وحدة تحكم Google Cloud ← **Billing → Budgets & alerts** — أكّد أن الميزانية
   نفسها تغطّي Cloud Functions وCloud Run وArtifact Registry.
3. AI Studio / Google Cloud ← مشروع Gemini API — راقب صفحة الحصة؛
   حدود الطبقة المجانية لـ `gemini-2.5-flash` هي السقف الطبيعي في الوقت الحالي.
4. `maxInstances: 10` في `index.js` هو الحدّ الصارم للتكلفة المتزامنة — أبقِه
   منخفضًا حتى تبرّر حركة المرور المزيد.

### بوابة الانحدار في CI (اختيارية، موصى بها)

اربط `node evals/run.js` بـ GitHub Actions كي يفشل البناء عند أي تغيير في الموجّه أو النموذج
يكسر الاستشهادات أو الرفض أو مقاومة الحقن. خزّن مفتاح
Gemini كسرّ مستودع. هذا آخر بند مفتوح في المرحلة 10.

## استكشاف الأخطاء وإصلاحها

| العَرَض | السبب المرجَّح |
|---|---|
| ما زالت الدردشة تقول *"not fully on duty"* | لم تُنشر الدالة، أو لم تُعد الاستضافة بعد النشر. |
| *"I couldn't reach my engine"* | الدالة منشورة لكنها تُخطئ — افحص `firebase functions:log --only chat`. |
| *"Ease off a moment, Captain"* | بلوغ حدّ المعدّل (HTTP 429) — متوقّع تحت الاستخدام الكثيف. ارفع متغيّرات البيئة `ADEL_RL_*` إذا تكرّر مع حركة دراسة عادية. |
| تُظهر السجلات *"request was not authenticated"* | دالة الجيل الثاني ليست عامة. يجب وجود `invoker: 'public'` في خيارات `onRequest` في `index.js` (وهو موجود)، ثم أعد نشر الدوال. أو امنح `allUsers` دور **Cloud Run Invoker** على خدمة `chat`. |
| `GEMINI_API_KEY is not configured` في السجلات | لم يُضبط السرّ، أو لم تُعد الدالة بعد ضبطه. |
| يفشل النشر على المنطقة | `me-central1` غير مفعّلة لمشروعك — بدّل كلا الموضعين إلى `us-central1` وأعد النشر. |
| أخطاء 429 / حصة من Gemini | حدّ معدّل Gemini API — ارفع الحصة في AI Studio، أو اخفض حركة المرور. |

## تذكيرات ما قبل الإطلاق

- الكابتن عادل **ذكاء اصطناعي تعليمي** — يقول إخلاء المسؤولية على الصفحة ذلك. أبقِه.
- مجموعة النصوص نصّ GACAR فقط؛ وتقع إشعارات NOTAM/الطقس الحيّة خارج
  النطاق عمدًا. يأمر موجّه النظام الكابتن برفض تلك.
- أكّد موقف إعادة توزيع GACAR مع المحامي السعودي (P0-1) قبل
  الإطلاق العام — راجع `office/lawyer-brief.md`.
