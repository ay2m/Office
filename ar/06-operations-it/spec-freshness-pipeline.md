# Fly GACA — خط معالجة حداثة المدوّنة — مواصفة التصميم

**الحالة:** تصميم، غير مبنيّ بعد · **يرتبط بـ:** البنود الشاملة في `roadmap.md` (حداثة AIP/AIRAC)،
المرحلة الثانية للابتلاع، المرحلة العاشرة · **أُعِدّ في:** 2026-05-30
**الوثيقة المرافقة:** `strategy-competitive-teardown.md`

يسمّي التفكيك التنافسي الحداثة بوصفها ضعفًا بنيويًّا لا يستطيع مشرف واحد الإمساك به
بشكل موثوق، ويصف أول استشهاد ملغى بأنه اللحظة التي يتصدّع فيها عرض الثقة لدينا. وتحوّل
هذه المواصفة تلك المسؤولية إلى **ضمان مرئيّ ومؤتمت ومختوم** — الموضع الوحيد الذي
سيهاجمه منافس مموّل، مُغلَقًا قبل أن يتمكّن منه.

يتغيّر AIP في كل **دورة AIRAC مدّتها 28 يومًا**؛ أمّا أجزاء GACAR فتُعدَّل بشكل غير منتظم. واليوم،
يجري تحديث كليهما يدويًّا. وتجعل هذه المواصفة التقادم *قابلًا للكشف ومؤرَّخًا ومحدودًا باتفاقية مستوى خدمة (SLA).*

> يعمل خط المعالجة على الخادم الافتراضي الخاص (VPS)، وهو **للبيانات العامة فقط** (`office/setup-vps.md`، حدود
> PDPL). يبتلع المدوّنة العامة ويقارن فروقها ويعيد بناء الفهارس؛ ولا يمسّ
> البيانات الشخصية أبدًا. وتُنشَر مخرجات العمل؛ ولا تعبر أي بيانات مستخدم الحدود.

## 1. ساعتا الحداثة

| فئة المصدر | الإيقاع | القيد |
|---|---|---|
| AIP (المطارات، الخرائط، AIS) | كل دورة AIRAC مدّتها 28 يومًا | يجب إظهار تاريخ السريان + "ليس للاستخدام التشغيلي" |
| أجزاء GACAR | تعديلات غير منتظمة | يجب تتبّع رقم/تاريخ التعديل وإعادة الابتلاع عند التغيير |
| الرف المرجعي (الكتيّبات، مراجع الإيكاو ICAO، FAA) | نادر | فرق منخفض الأولوية |

يحمل كل أثر عمل في `assets/data/` ومدوّنة RAG (`functions/rag/_chunks.json.gz`)
**بيانات المصدرية الوصفية** بحيث تكون الحداثة خاصيّة من خصائص البيانات، لا معرفة شفهية.

## 2. بيانات المصدرية الوصفية (تُضاف إلى كل عنصر في المدوّنة)

```jsonc
{
  "source_id": "gacar-part-61",
  "source_class": "gacar",          // gacar | aip | reference
  "source_url": "https://gaca.gov.sa/...",   // النسخة الرسمية المعتمدة
  "fetched_at": "2026-05-30T00:00:00Z",
  "effective": { "airac": "2026-06", "from": "2026-06-11" }, // aip فقط
  "amendment": "Amdt 3 (2025-11)",   // gacar فقط
  "content_hash": "sha256:…",        // يقود كشف التغيير
  "verified_cycle": "2026-05"        // آخر دورة أكّد فيها إنسان/CI الحداثة
}
```

## 3. مراحل خط المعالجة (cron على الخادم الافتراضي الخاص)

1. **الجلب** — اسحب النسخ الرسمية المعتمدة لكل مصدر متتبَّع.
2. **التجزئة والفرق** — قارن `content_hash` بآخر بناء. دون تغيير ← تخطٍّ. متغيّر
   ← علِّم لإعادة الابتلاع. تُفحص مصادر AIP وفق تقويم AIRAC بغضّ النظر عن التجزئة.
3. **إعادة الابتلاع** — أعد التحليل ← التقطيع ← إعادة التضمين للمصادر المتغيّرة فقط (تزايديًّا، لا
   إعادة بناء كاملة). أعد استخدام شيفرة الابتلاع الموجودة من المرحلة الثانية (`assistant/rag.py`،
   `functions/rag/`).
4. **الختم** — اكتب/حدّث كتلة المصدرية وارفع `verified_cycle`.
5. **التحقق** — شغّل حزمة التقييم (`evals/`) على المدوّنة المعاد بناؤها؛ فأي استشهاد
   لم يعد يُحلّ إلى قسم حيّ **يُفشِل البناء** (يرتبط ببوابة تقييم CI في المرحلة العاشرة).
6. **النشر** — انشر `assets/data/` المُحدَّثة + فهرس RAG المعاد بناؤه؛ ووسِم النشر
   بدورة AIRAC.

```
fetch → hash/diff → [changed?] → re-ingest → stamp → eval-gate → publish
                       │no
                       └────────────────────────────────→ skip (log "current")
```

## 4. الضمان المرئي للمستخدم (السطح التسويقي)

- **ختم حداثة على كل صفحة قارئ**: "GACAR Part 61 — Amdt 3, verified AIRAC 2026-05"
  / "AIP AD — effective AIRAC 2026-06 · not for operational use." أعد استخدام منطق الدورة
  في أداة حاسبة AIRAC الموجودة.
- **شريط تقادم**: إذا كانت `verified_cycle` أقدم من دورة AIRAC الحالية لعنصر من
  فئة AIP، تُظهِر الصفحة تلقائيًّا "التحقق معلّق للدورة الحالية — تأكّد
  من نسخة AIP الرسمية."
- **سطر حالة عام** ("المدوّنة محدّثة اعتبارًا من AIRAC YYYY-CC") على واجهة المكتبة.

هذا هو عامل التمييز: *محدّثة دائمًا، يُتحقَّق منها كل دورة، مع التاريخ على الصفحة* —
ادعاء لا يستطيع مشرف يدوي واحد تقديمه بمصداقية ويمكن لمنافس عندئذٍ أن يسوّق
ضدّه. وما يجعله حقيقيًّا لا تطلّعيًّا هو الفرق + الختم + بوابة التقييم المؤتمتة.

## 5. تكامل الكابتن عادل

- يفضّل الاسترجاع المقطع الأحدث؛ وتُستبعَد المقاطع الملغاة من الفهرس، لا
  يُخفَّض ترتيبها فحسب.
- يستشهد موجّه النظام أصلًا بالجزء الدقيق؛ وسّع الاستشهادات لتشمل
  **ختم التعديل / AIRAC** بحيث تكون الإجابة مؤرَّخة، لا مصدَّرة فحسب.
- تكتسب حزمة التقييم **فئة حالات تقادم**: فالإجابة التي تستشهد بمصدر ملغى تُعدّ
  إخفاقًا قاطعًا، إلى جانب حالات الاستشهاد/الرفض/الحقن الموجودة.

## 6. اتفاقية مستوى الخدمة (SLA) (الالتزام الذي يمكّننا خط المعالجة من الوفاء به)

| فئة المصدر | هدف التحديث |
|---|---|
| فئة AIP | إعادة التحقق خلال **أول 72 ساعة من كل دورة AIRAC جديدة** |
| GACAR | إعادة الابتلاع خلال **7 أيام** من تعديل مكتشَف |
| المرجع | بأفضل جهد، فرق شهري |

## 7. ما الذي يُبنى، بالترتيب

1. أضِف كتلة المصدرية إلى مخطّط المدوّنة + استكمل العناصر الموجودة بأثر رجعي.
2. مهمّة الجلب + التجزئة/الفرق (كشف التغيير) — أرخص خطوة أولى وأعلاها قيمة.
3. ختم حداثة صفحة القارئ + شريط التقادم (مكسب مرئي للمستخدم، بجهد صغير).
4. إعادة الابتلاع التزايدية موصولة بمخرجات الفرق.
5. حالة تقييم التقادم + بوابة CI (تقترن بعمل تقييم CI في المرحلة العاشرة).
6. سطر الحالة العام "محدّثة اعتبارًا من AIRAC".

تحوّل الخطوات 1–3 وحدها الضعف إلى قوّة مسوَّقة؛ وتجعل الخطوات 4–6 الضمان
قائمًا بذاته.
