# Fly GACA — دليل تشغيل تحديثات المصادر

كيف تُبقي فلاي قاكا **GACAR** و**AIP** وبقية متن الهيئة العامة للطيران المدني
متوافقة مع منشورات الهيئة نفسها — تلقائيًا، وفق وتيرة AIRAC.

## الخلاصة

يتفقّد إجراء GitHub Action مُجدوَل الصفحات الرسمية للهيئة العامة للطيران المدني، ويُنزّل كل جديد،
ويحدّث الفهارس، ويحرس سلامة البيانات، ويلتزم بالنتيجة. ولا حاجة بك
إلى فعل أي شيء في الدورات الاعتيادية.

```bash
# Manually, from a machine that can reach gaca.gov.sa:
npm run check:sources     # is anything new on GACA? (no writes; exit 1 if drift)
npm run update:sources    # download new docs + refresh indexes + status file
```

## ما الذي جرى ربطه

| المكوّن | المسار | الدور |
|-------|------|------|
| بيان المصادر | `assets/data/sources.json` | عناوين URL الرسمية للهيئة العامة للطيران المدني، وإعداد AIRAC، والبصمات لكل مصدر. يملك المُحدِّث البصمات — لا تحرّرها يدويًا. |
| محرّك التحديث | `scripts/update-sources.js` | يجلب كل صفحة من صفحات الهيئة، ويكتشف المستندات المنشورة، ويرصد التغيير، ويُنزّل الملفات الجديدة، ويحدّث الفهارس. دون أي اعتماديات. |
| ملف الحداثة | `assets/data/source-status.json` | لقطة عامة مُولَّدة تلقائيًا — آخر تفقّد، وAIRAC الحالي/التالي، وحالة كل مصدر. آمنة للشحن؛ ويمكن للتطبيق عرض "GACAR محدّث حتى …". |
| الجدولة | `.github/workflows/update-sources.yml` | أسبوعيًا (الإثنين) + كل خميس (لالتقاط تواريخ سريان AIRAC) + التشغيل اليدوي. |

## المصادر المتتبَّعة (مجموعة "كل شيء من الهيئة العامة للطيران المدني")

| id | ما هو | URL |
|----|------|-----|
| `gacar` | أجزاء GACAR وإطارها | https://gaca.gov.sa/en/Rules-and-Regulations-Category |
| `aip` / `aerodromes` / `charts` | AIP / eAIP، وAD 2، ومخططات VFR (مرتبطة بـ AIRAC) | https://gaca.gov.sa/web/en/aeronautical-information |
| `advisory-circulars` | AC-xxx | https://gaca.gov.sa/web/en/advisory-circulars |
| `notam` | NOTAM / PIB (حسّاسة زمنيًا) | https://gaca.gov.sa/web/en/notam |

## وتيرة AIRAC

تتبع حداثة AIP دورة AIRAC البالغة 28 يومًا. يحسب المُحدِّث تاريخي السريان
الحالي والتالي من المرساة في `sources.json` (`airac.anchor`،
`airac.cycleDays`). وتختم المصادر المرتبطة بـ AIRAC تاريخ `generated` في فهرسها
بـ**تاريخ سريان AIRAC**، لا بتاريخ التشغيل، بحيث يطابق التاريخ المنشور
الدورة. ويتوافق التشغيل الدوري ليوم الخميس في سير العمل مع أيام خميس AIRAC.

## كيف يجري تشغيل ما

1. اجلب كل صفحة مفعَّلة من صفحات الهيئة العامة للطيران المدني (مع عمليات إعادة التوجيه، وإعادات المحاولة، ومهلة 25 ثانية).
2. اكتشف كل رابط مستند (PDF / صيغ المكتب) وابصم المجموعة.
3. قارن بالبصمة المسجَّلة ← أتغيّرت؟
4. عند التغيير (`--apply`): نزّل الملفات الجديدة إلى `library/<staging>/`، وشغّل
   `pdftotext` على ملفات PDF عند توفّره، وارفع تاريخ `generated` للفهرس المتأثر،
   وحدّث البصمة، وأعد كتابة `source-status.json`.
5. يبوّب `node scripts/check-data.js` النتيجة — إذ تفشل مجموعة بيانات تالفة أو
   منحرفة في العدّ في التشغيل قبل الالتزام بأي شيء.
6. التزم بـ `assets/data/` وادفع. (اختياريًا انشر — انظر أدناه.)

## السلوك الآمن من الفشل

- **الجلب المحظور أو الفارغ لا يمسح المحتوى أبدًا.** إذا فجأة سردت صفحة كانت تحوي
  مستندات صفرًا منها، فإن المُحدِّث يعاملها كخطأ جلب
  ولا يغيّر شيئًا.
- **`--check` يفشل فقط عند تغيير إيجابي.** أمّا متاعب الشبكة فتحذير
  لين (exit 0)، بحيث لا تنبّه الجدولة أحدًا أبدًا بسبب جلب متقطّع.
- **`library/` تجهيز مستثنى من git.** ولا يُلتزم ويُنشر سوى `assets/data/`
  المعالَجة (بموجب `library/README.md`). أمّا ملفات PDF المُنزَّلة فتقطن في
  المشغِّل لأجل استخراج ذلك التشغيل؛ ولا يُلتزم بها.

## جعل النشر تلقائيًا بالكامل (نشر اختياري)

عمليات النشر يدوية فيما عدا ذلك (`firebase deploy`)، والدفعة التي يجريها رمز سير العمل
الافتراضي **لا** تعيد إطلاق مهمة النشر في `ci.yml`. ولذا، كي تتيح لهذا
السير العمل النشر بنفسه، أضف سرّ مستودع **`FIREBASE_TOKEN`** (من
`firebase login:ci`). تنشر الخطوة الأخيرة في سير العمل الاستضافة فقط عند وجود ذلك
السرّ والتزام تغيير. وبدون السرّ، تُلتزم البيانات
ويشحنها النشر الاعتيادي التالي.

## أول تشغيل حيّ — ضبط الكاشط

لم يكن بالإمكان اختبار خط الأنابيب هذا مقابل `gaca.gov.sa` من صندوق البناء الرملي
(إذ تُرجع قائمة الشبكة المسموح بها `403 Host not in allowlist` لذلك المضيف)، ولذا فإن
اكتشاف الروابط هو بذل جهد متسامح: يسحب كل `<a href>` ينتهي بـ
`.pdf/.doc/.docx/.xls/.xlsx/.zip`. وعند أول تشغيل حقيقي، تفقّد أعداد `N docs`
لكل مصدر في سجل سير العمل:

- **0 مستندات على مصدر ينبغي أن يحوي الكثير** ← تخدم الهيئة العامة للطيران المدني تلك القائمة عبر
  صيغة يفوتها التعبير النمطي (مثل روابط دون امتداد ملف، أو تغذية API/JSON).
  وسّع نمط `EXT` أو منطق الاكتشاف في
  `scripts/update-sources.js` (`discover()`)، أو وجّه `url` المصدر إلى
  الصفحة التي تسرد الملفات فعليًا.
- يعني السلوك الآمن من الفشل لدى المُحدِّث أن المُحدِّد سيّئ الضبط يُبلِّغ عن "0 / error" ولا
  يغيّر شيئًا — فلن يُتلف البيانات الحيّة أثناء ضبطك له.

## استخراج المحتوى العميق (نقطة الإضافة)

يحصل المُحدِّث على **ملفات المصدر** ويُبقي **حداثة الفهارس**
متوافقة تلقائيًا. أمّا تحويل ملف PDF محدّث إلى HTML القراءة لكل جزء
(`assets/data/parts/*.html`) وإلى فهرس بحث المكتبة بكاملها فهو الخطوة الوحيدة
التي تحتاج إلى البنية الفعلية لمستند الهيئة العامة للطيران المدني (انظر
`office/content-integration-plan.md`). أضف ذلك التحويل بوصفه
`scripts/extract-sources.js` واستدعِه من سير العمل بين الجلب
وحارس السلامة؛ ويجب أن تتحرك معه الأعداد في `check-data.js` وملف README
(فهي تعاقدية).

*دليل تشغيل تشغيلي — وليس استشارة قانونية. تبقى الهيئة العامة للطيران المدني المصدر ذا الحجية.*
